## 1. 网络：先纠正一个错误结论

上一版报告写"本机连不上外网 DNS"——**这是错的**，错在测试用了假域名 `x`。
实际网络拓扑：

| 通道 | 配置 |
|---|---|
| WinINET 代理（浏览器/curl 走这条） | `http://127.0.0.1:65532`，监听进程 `nano` |
| 环境变量 / WinHTTP | **空 + 直连**（所以 PowerShell / Python / requests 默认不走代理） |
| DNS | `10.149.45.174`（阿里云集群解析） |

连通性矩阵：

| 目标 | 直连 | 走代理 |
|---|---|---|
| `www.yuketang.cn` | **200** | 200 |
| `api.github.com` | **200** | 403（代理不给） |
| `example.com` / `raw.githubusercontent.com` / `pypi.org` | 000 | 200 |

**结论：国内站点直连可达，境外需显式 `-x http://127.0.0.1:65532`（但代理会拦 api.github.com）。**
这直接让"线上验证"成为可能。

### 2.2 ⚠️ 脚本的关键选择器已被改版废掉

脚本用 `document.querySelector('.progress-wrap')?.querySelector('.text')` 取进度。
线上 `progress-wrap` 组件（`study-progress`）的真实渲染：

```js
n("div",{staticClass:"progress-wrap"},[
  n("el-tooltip",{staticClass:"item",attrs:{"popper-class":"progress-tooltip",...}},[
    n("div",{attrs:{slot:"content"},slot:"content"},[
      0==e.schedule ? ... "未开始"
      : e.schedule<1 ? n("span",{staticClass:"f16 font-weight500"},[Math.round(100*e.schedule)]),
                       n("span",{staticClass:"f12"},["%"])
      : n("div",{staticClass:"f12 color-9b"},["已完成"])
    ])
  ])
])
```

**结论：**
- 子树里**没有 `.text` 类** → 原脚本取到 `null`
- `isProgressDone(null)` 恒为 `false` → 轮询永远不满足 → **每个视频都要卡到截止时间才跳**
- 百分比还被拆成两个元素（`98` 和 `%`），且在 tooltip 的 content slot 里

这比 98% 那个 bug 更致命，也是"落后一个版本就刷不满"的真正原因之一。

## 4. 字体混淆解码：实测 93%，并挖出两个真 bug

### 4.1 方法

用 fontTools 造了个**真实可用的混淆字体**（把字符 A 的字形替换成字符 B 的字形，
与雨课堂 `xuetangx-com-encrypted-font` 同构），语料取自仓库自带的真实课程答案文件
（754 个去重汉字），随机 100 对混淆，**直接调仓库原函数**，算法一行没改。

### 4.2 结果

| 指标 | 结果 |
|---|---|
| 混淆字符还原率 | **93 / 100 = 93.0%** |
| 正常字符准确率（无误伤） | **100 / 100** |
| 识别速度 | 12 ms/字 |
| 完整中文字体（28,522 字）首次建表 | **约 5-6 分钟**，之后走 `font_cache/*.json` 缓存 |

### 4.3 关键推论：单字 93% ≠ 整题可靠

| 题干字数 | 至少一个错字的概率 |
|---|---|
| 20 字 | 76.6% |
| 50 字 | **97.3%** |
| 100 字 | 99.9% |

**这正是那些仓库自评"纯文本大模型得分率 75%~85%"的成因之一**——误差不只来自模型。

渲染参数调优无效：1024px→64px、1bit/灰度、JPEG/PNG，准确率**恒为 93.0%**，
误差来自 ddddocr 的形近字混淆（`四→节`、`程→求`、`检→念`…），不是分辨率问题。

### 4.4 两个真实缺陷

**缺陷 A：正则太脆（9 种写法只认 4 种）**

原版正则 `<span\s+class="xuetangx-com-encrypted-font"\s*>(.*?)</span>`：

| span 写法 | 原版 | 修复版 |
|---|---|---|
| `class="xuetangx-com-encrypted-font"` | ✅ | ✅ |
| `class="xuetangx-com-encrypted-font foo"` | ❌ | ✅ |
| `style="..." class="..."` | ❌ | ✅ |
| `class='...'`（单引号） | ❌ | ✅ |
| `CLASS="..."`（大写） | ❌ | ✅ |
| span 内容跨行 | ❌ | ✅ |
| `> ` 前有空格 / 属性换行 / 多个 span | ✅ | ✅ |

**4/9 → 9/9。** 匹配失败时题干不解密就喂给大模型 = 送乱题 = 静默答错。

**缺陷 B：WOFF2 解析不了，但代码却在处理 woff2**

`requirements.txt` 没有 `brotli`，而 `load_or_build_font_map()` 明确会缓存 `.woff2`。
实测 `TTFont()` 读 woff2 → `ImportError: No module named brotli`，仓库 catch 掉后
"尝试不解密继续" → 又是静默答错。`pip install brotli` 仅 343ms。

双环境对照验证（装了 / 没装 brotli 两个 venv，同一份 woff2 样本）：

| 用例 | 无 brotli | 有 brotli |
|---|---|---|
| 修复版 `ttf_parse` 读 woff2 | `RuntimeError: 解析字体失败：WOFF2 需要 brotli 支持，请执行 pip install brotli` ✅ | 成功，14 条映射 ✅ |
| 原版 `ttf_parse` 读 woff2 | `ImportError: No module named brotli` ← 裸异常 | 成功 |
| 修复版空映射 | `RuntimeError: 字体映射表为空…请改用截图交给多模态模型。` ✅ | 同左 ✅ |
| **原版空映射** | **没有抛异常** ← 静默返回空表 | 同左 |
